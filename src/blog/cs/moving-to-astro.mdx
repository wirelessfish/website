Oukej, abys měl nějaký kontext: moje webovka používala [Eleventy](https://www.11ty.dev/) jako static site generator od commitu
[141d103](https://github.com/wirelessfish/website/commit/141d103337e7ba7e349cec8d05aa5660aa627680)
(2025/06/07 - wow, to už je 7 měsíců). Bylo to v pohodě rozhodnutí, protože jsem se tehdy potřeboval vyhnout kopírování mojí navigace
na každou stránku.

11ty je super (stejně jako jejich maskot)! Je perfektní pro automatické vkládání html kódu jako třeba u jednoduchých blogů. Jenomže problémy
se začnou oběvovat, když se snažíte dosáhnout něčeho více než jen to. Když jsem chtěl přejít od jednoduchých html úryvků na reálné komponenty, tak jsem nemohl,
protože na to Eleventy jednodužše není postavený. No a pak musíš manuálně manipulovat DOM, jenom proto abys mohl mít návštěvnickou knihu.
[Pročpak to asi vím](https://github.com/wirelessfish/website/blob/52f49ba1e4f89ac7559efc5e938e10c9957563e5/src/scripts/guestbook.ts).

Nemluvě o poněkud nedostatečné dokumentaci (dá se v tom vyznat jenom díky AI). Všechy tyhle věci vedly k tomu, že se mi Eleventy spíše ztěžovala život. Tak jsem
se konečně sebral a předělal celou stránku tak, aby používala Astro a Svelte přes cca týden.

## To dobré

### Komunita

Dokumentace je teď doopravdy užitečná! Jak Astro tak Svelte mají super dokumentaci a v kombinaci se svými obrovskými komunitami je mnohem jednodužší
najít a opravit chyby v kódu.

### Integrace

Integrace Svelte do Astro frameworku je velmi jednoduché:

```bash
pnpm astro add svelte
```

A hotovo!

### Komponenty!!!! &lt;3

Teď, když mám sílu komponentů na mojí straně, můžu dělat to o čem může Eleventy jenom snít:

```svelte
<AeroButton color={"#1e78ff"}>Čudlík 1</AeroButton>
<AeroButton color={"#9d41da"}>Čudlík 2</AeroButton>
<AeroButton color={"#ffb41f"}>Čudlík 3</AeroButton>
<AeroButton color={"#ff1e1e"}>Čudlík 4</AeroButton>
<AeroButton color={"#ec5757"}>Čudlík 5</AeroButton>
```

Tento úryvek vytvoří tohle:

<AeroButton color={"#1e78ff"}>Čudlík 1</AeroButton>
<AeroButton color={"#9d41da"}>Čudlík 2</AeroButton>
<AeroButton color={"#ffb41f"}>Čudlík 3</AeroButton>
<AeroButton color={"#ff1e1e"}>Čudlík 4</AeroButton>
<AeroButton color={"#ec5757"}>Čudlík 5</AeroButton>

Vidíš to? Čudlík si automaticky vypočítá barvy na základě jen jedné, která je nadefinována! Velmi cool!

Využívá to npm klinovnu `color` pro manipulaci s barvami a cca dělá tohle:

```ts
let border = original_color.lighten(0.5).fade(0.5);

// Regular colors
let regular = {
  base: original_color,
  lighter: original_color.lighten(0.3),
};

// Colors for hovering over the button
let hover = {
  base: regular.base.darken(0.15),
  lighter: regular.lighter.darken(0.15),
};
```

Neprůstřelná implementace? Určitě ne. Šlo by to udělat s více css a méně javascriptu? Určitě. Ale mě se líbí tahle implementace. Udělal jsem ji já a jsem s ní
spokojenej (prozatím lol).

### Interaktivita / skriptování

Další věc co mi Astro a Svelte dovolí je jednoduchá modifikace DOMu (obsahu stránky)! Jednoduše nadefinuju proměnnou pomocí `$state()` (ve Svelte komponentech),
použiju ju ve stránce a kdykoliv kdy se ta proměnná změní, změní se i obsah stránky!

<ChangingShowcase locale="cs" client:only />

Příklad nad tímhle _zhruba_ potřebuje tento kód:

```svelte
<script>
// import {sleep} from ...
let words = ["Můžu tyhle", "slova měnit", "dost jednodužše", "za pomocí", "Svelte komponentů!"];
let current_word: number = $state(0);

while (true) {
  current_word += 1;

  if (current_word >= words.length) {
    current_word = 0;
  }

  await sleep(1500);
}
</script>

<div>
  {words[current_word]}
</div>
```

Přímo tento příklad není o moc rozdílný od toho, když získáme element za pomoci `document.getElementById()` a změníme `innerHtml` proměnou. Ale takový přístup
začne vypadat hodně škaredě hodně rychle. Obzvlášť jakmile musíte aktualizovat třeba přes čtyři proměnné. Navíc Eleventy by vyžadoval rozdělení HTML, CSS a
Javascriptu do jednotlivých souborů kdežto Svelte vám dovolí mít vše v jednom souboru. Díky tomuto je zdrojový kód se Svelte o dost přehlednější.

Tohle je velmi užitečné pro věci jako... moje [návštěvnická kniha](/cs/guestbook/) (kterou by jsi měl určitě podepsat btw) nebo takový ten status na boku stránky!
Ty soubory obsahují vše co potřebují k fungování a můžu potom stránku stavět jako z LEGO kostek. A když něco potřebuje pozměnit, vše k jedné stavební kostce
je obsaženo právě v jejím souboru \:D

## To špatné

Zatím jsem neměl žádné problémy s Astro. Má vše co potřebuju a extra věci můžu přidat pomocí dalších npm knihoven. Dost se těším se na další programování s Astro.

## Doporučoval bys Eleventy/Astro?

Eleventy rozhodně není špatná volba, ale je tam o dost více práce při prvním nastavení oproti Astro. Pokud jenom potřebuješ jednoduché layouty a html úryvky a
nevadí ti to nastavování, tak je to asi ta správná volba pro tebe. Ale když chceš cokliv více (nejspíš ano, komponenty jsou mega super) tak bych spíše doporučoval
Astro s frameworkem jako Svelte.

Astro je super, compiluje se na statické stránky jako Eleventy (perfektní pro nekoweb nebo neocities) a zůstává rychlé díky javascript ostrůvkům (upřímě se mě neptej
co přesně to znamená, můžeš si to načíst [tady](https://docs.astro.build/en/concepts/islands/)).
